# CLI-координация

Диспетчер `tools/agents.mjs` передаёт задания двум CLI. Codex использует `workspace-write`, Antigravity — `accept-edits` и terminal sandbox. Авторизация берётся из существующих пользовательских настроек. Флаги отключения sandbox и обхода разрешений не используются.

У каждого агента отдельный зарегистрированный worktree и ветка. Из корня репозитория:

```powershell
git worktree add -b agent/backend ../kindergarten-backend main
git worktree add -b agent/frontend ../kindergarten-frontend main
node tools/agents.mjs tasks/smoke.json
```

Если worktree уже создан, повторное создание не требуется. Пути в манифестах указывают на соседние каталоги. В `tasks/build.json` закреплены выбранные владельцем модели `gpt-6.1-sol` и `gemini-3.8-flash-high`.

Манифест задаёт массив задач с полями `id`, `provider`, `model`, `worktree`, `branch`, `prompt` и необязательным `sessionId`. Prompt — путь к UTF-8 файлу из корня репозитория. `sessionId` позволяет продолжать чат Codex на том же компьютере после завершения предыдущего процесса. Для нового компьютера поле удаляется. Все задания проверяются до запуска.

Блокировки и логи хранятся в `.agent-runs/`, исключённой из Git. Для одного worktree допускается один активный диспетчер. Команда ждёт завершения задач, сохраняет stdout, stderr, result и summary. Успешный CLI-ход получает статус `review_required`. Координатор читает diff и выполняет проверки перед принятием результата.

Лимит по умолчанию — 3600 секунд на задачу. Переменная `AGENT_TIMEOUT_SECONDS` меняет его. Ctrl+C останавливает деревья процессов, созданные диспетчером. Если аварийное завершение оставило lock-файл, перед удалением проверяются записанный PID и логи.

У чата Codex один активный писатель. Во время автоматической разработки наблюдать можно по логам. После завершения процесса историю открывают командой `codex resume <thread-id> --model gpt-6.1-sol` из backend-worktree. ID находится в событии `thread.started` журнала. Antigravity получает задания через один активный CLI-процесс.

Одна команда запускает один раунд. Следующий раунд и проверку выполняет координатор в активном чате. Доступность моделей, лимиты и авторизация определяются аккаунтами пользователя. Headless CLI может завершиться успешно после отказа отдельному инструменту, поэтому дополнительно проверяются диагностика и фактические файлы. Слияние выполняется после проверки.
