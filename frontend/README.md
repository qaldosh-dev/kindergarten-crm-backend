# Веб-приложение детского сада (Frontend)

Фронтенд веб-приложения для управления частным детским садом, учёта посещаемости и автоматизированного расчёта родительской платы за питание.

Разработано на **React 18 + TypeScript + Vite** с соблюдением требований [docs/specification.md](../docs/specification.md) и точного контракта API [docs/api-contract.md](../docs/api-contract.md).

---

## 1. Стек технологий и архитектура

- **Фреймворк и сборщик:** React 18, TypeScript 5, Vite 6.
- **Маршрутизация:** `react-router-dom` v7 с разграничением ролей (`RoleGuard`), перенаправлениями и строгой защитой маршрутов.
- **Иконки:** `lucide-react`.
- **Стили и тема:** Собственная модульная дизайн-система в сдержанной палитре **кремовый / тёмно-синий / чирок (cream/navy/teal)**.
  - Фон: теплый оттенок слоновой кости / крем (`#fbfaf7`).
  - Тексты, шапки, навигация: глубокий тёмно-синий (`#0f172a`, `#1e293b`).
  - Акценты и активные элементы: чирок (`#0d9488`, `#0f766e`).
  - Предупреждения и задолженности: тёплый янтарь (`#d97706`) и приглушённый красный (`#dc2626`).
  - Типографика: Inter и системный стек шрифтов, моноширинные табличные цифры (`font-variant-numeric: tabular-nums`).
- **Сетевой клиент:** Типизированный `apiClient` на базе Fetch API.
  - **Безопасность JWT:** Access token хранится **исключительно в оперативной памяти** (in-memory). Никаких сохранений в `localStorage` или `cookies`. При перезагрузке страницы требуется повторный вход.
  - **Обработка 401 Unauthorized:** Автоматический перехват, очистка памяти авторизации и перевод пользователя на экран входа с сообщением об истечении сессии.
  - **Обработка ошибок:** Полный парсинг `application/problem+json` (`status`, `title`, `detail`, `code`, `fieldErrors`, `conflictDates`).
  - **Идемпотентность финансовых операций:** Класс `IdempotencyTracker` генерирует UUID v4, гарантированно сохраняет его при повторных попытках отправки неизменённого тела запроса и обновляет ключ при успехе или изменении параметров. Кнопки защищены от повторного нажатия во время ожидания ответа сервера (`disabled` + индикатор загрузки).
  - **Отсутствие моков:** Приложение полностью работает с реальным API (`/api/v1`). Никаких фейковых успешных ответов и захардкоженных финансовых расчётов на стороне клиента.

## 2. Реализованные экраны и возможности

### Аутентификация и безопасность
- **Вход в систему (`/login`):** форма авторизации по логину и паролю, показ ошибок сервера, кнопки быстрого заполнения демо-данными:
  - Администратор: `admin@demo.local` / `DemoAdmin2026!`
  - Воспитатель: `teacher@demo.local` / `DemoTeacher2026!`
- **Принудительная смена пароля:** если у пользователя выставлен флаг `mustChangePassword: true` (при первом входе или после сброса администратором), отображается блокирующий диалог смены пароля. После смены пароля сервер инвалидирует токены, и пользователь выполняет вход с новым постоянным паролем.
- **Добровольная смена пароля:** доступна из шапки профиля в любое время.
- **Выход из системы:** мгновенная очистка токена из памяти и редирект.

### Кабинет воспитателя (Роль `TEACHER`)
- **Журнал посещаемости (`/teacher`):**
  - Автоматическая загрузка групп, назначенных текущему воспитателю на сегодня (`GET /api/v1/teacher/groups`).
  - Выбор группы, если назначено несколько.
  - Календарный выбор даты. Для прошлых дат включается **режим только чтение** с информационным баннером.
  - Отметка детей за сегодня: «Не отмечено» (`null`), «Присутствует» (`PRESENT`), «Отсутствует» (`ABSENT`).
  - Кнопка **«Все присутствуют»** с явным требованием сохранения (изменения фиксируются локально до нажатия «Сохранить»).
  - Индикатор количества несохранённых изменений и кнопка отмены правок.
  - Атомарное сохранение группы (`PUT /api/v1/groups/{id}/attendance?date=...`).
  - Обработка конфликтов оптимистичной блокировки (409 Conflict) с возможностью перезагрузить актуальные данные.

### Панель администратора (Роль `ADMIN`)

1. **Обзор (`/admin`):**
   - Ключевые показатели за текущий месяц (`GET /api/v1/reports/billing?month=...`): начислено по счетам, поступило оплат, возвраты родителям, текущий общий долг, авансовые переплаты.
   - Предупреждающий блок детей, требующих сверки счетов (`needsReconciliation: true`) после изменения справок или календаря.
   - Быстрый переход к разделам.

2. **Список детей (`/admin/children`):**
   - Поиск по ФИО, фильтрация по группе и статусу (активные / выбывшие).
   - Пагинация реестра.
   - Диалог зачисления нового ребёнка (`POST /api/v1/children`): ФИО, дата рождения, дата поступления, группа, комментарий и динамический список контактов родителей.

3. **Карточка ребёнка (`/admin/children/:id`):**
   - **Карточка и контакты:** редактирование личных данных и списка законных представителей (`PATCH /api/v1/children/{id}`).
   - **Выбытие и возобновление зачисления:** установка даты выбытия (`PUT /api/v1/children/{id}/withdrawal`) или её аннулирование.
   - **История групп:** просмотр периодов пребывания, перевод в новую группу (`POST /api/v1/children/{id}/group-memberships`) с автоматическим закрытием предыдущего членства вчерашним днём, исправление периодов с указанием причины (`PATCH /group-memberships/{id}`).
   - **Лицевой счёт и баланс:** текущая позиция (долг/переплата), реестр бухгалтерских проводок (Главная книга), действия:
     - Ввод начального остатка (`POST /children/{id}/opening-balance`).
     - Ручная корректировка с обязательной причиной (`POST /children/{id}/adjustments`).
     - Оформление возврата переплаты родителю с контролем доступного кредита (`POST /children/{id}/refunds`).
   - **Справки о болезни:** регистрация справки (`POST /children/{id}/illness-certificates`), проверка задержки сдачи (> 7 дней), **обработка конфликта посещаемости (409 ATTENDANCE_CONFLICT)** с показом спорных дат и явным подтверждением перезаписи (`confirmAttendanceOverride: true`), отзыв справки с фиксацией причины (`POST /illness-certificates/{id}/revoke`).
   - **Индивидуальная цена:** назначение скидки/надбавки на период с обоснованием (`POST /children/{id}/price-overrides`) и редактирование версий (`PATCH /price-overrides/{id}`).

4. **Группы и персонал (`/admin/groups`):**
   - Создание и редактирование групп (`POST /groups`, `PATCH /groups/{id}`).
   - Расписание и история назначений воспитателей на группу (`GET /groups/{id}/teacher-assignments`, `POST /groups/{id}/teacher-assignments`, `PATCH /teacher-assignments/{id}`).
   - Управление сотрудниками: создание воспитателя (`POST /users`), изменение логина, блокировка/разблокировка (`PATCH /users/{id}`), сброс пароля с обязательной сменой при входе (`POST /users/{id}/reset-password`).

5. **Исправление посещаемости (`/admin/attendance`):**
   - Выбор любой группы и любой даты.
   - Корректировка отметок с обязательным указанием причины исправления для сохранения в аудите.

6. **Календарь и тарифы (`/admin/calendar-tariffs`):**
   - Интерактивный календарь месяца: четкое визуальное разделение рабочих дней, выходных, государственных праздников (`baseWorking=false`) и **внеплановых закрытий сада (`closed=true, baseWorking=true`)**, сохраняющих общий знаменатель рабочих дней.
   - Атомарное обновление календаря месяца (`PUT /api/v1/calendar/{year}/{month}`).
   - Возрастные тарифы: просмотр и создание новых версий тарифной сетки [0,2), [2,4), [4,∞) с датами действия и причинами изменений (`GET /tariffs`, `POST /tariffs`, `PATCH /tariffs/{id}`).

7. **Расчёты и счета (`/admin/billing`):**
   - Выбор расчётного месяца.
   - Запуск пакетного предварительного расчёта (`POST /api/v1/billing/months/{month}/calculate`) с модальным окном результатов по каждому ребёнку (`CALCULATED`, `ALREADY_ISSUED`, `ERROR`).
   - Реестр счетов с фильтрацией по статусам (`DRAFT`, `ISSUED`).
   - Просмотр детализации формулы счёта: количество рабочих дней $W$, оплачиваемых дней $P$, расшифровка исключённых дней с причинами (`ILLNESS`, `CLOSED`, `OUTSIDE_ENROLLMENT`), тарифные периоды и текстовое объяснение алгоритма.
   - Выставление счёта (`POST /api/v1/invoices/{id}/issue`) со сроком оплаты (по умолчанию 10-е число, с обязательным явным вводом при выставлении после 10-го числа).
   - Предварительный просмотр сверки (`POST /invoices/{id}/reconciliation-preview`) под транзакционной блокировкой backend с расчётом разницы и подтверждение сверки с причиной (`POST /invoices/{id}/reconcile`).

8. **Платежи (`/admin/payments`):**
   - Реестр оплат с фильтрацией по месяцу и ребёнку.
   - Регистрация платежа (`POST /api/v1/payments`) наличными или безналичным переводом с защитой ключом идемпотентности.
   - Отмена платежа (`POST /api/v1/payments/{id}/cancel`) с обязательным объяснением причины и автоматическим пересчётом покрытия начислений.

9. **Отчёты (`/admin/reports`):**
   - Сводная таблица месяца: начисления, оплаты, возвраты, сальдо, долг, переплата и статус необходимости сверки по каждому ребёнку.
   - Экспорт отчёта в кодировке UTF-8 в формате CSV (`GET /api/v1/reports/billing.csv?month=...`).

10. **Журнал аудита (`/admin/audit`):**
    - Просмотр системных событий (`GET /api/v1/audit-events`).
    - Фильтрация по типу сущности, идентификатору сущности и идентификатору автора.
    - Просмотр снимков состояния объекта «ДО» и «ПОСЛЕ» в формате JSON.

## 3. Сборка и запуск

### Требования
- Node.js 22 LTS или новее.
- npm или pnpm.

### Локальная разработка
```bash
cd frontend
npm ci
npm run dev
```
Интерфейс доступен по адресу `http://localhost:5173`.
Запросы к `/api` и `/actuator` проксируются на `http://localhost:8080`.

### Проверка типов и сборка для production
```bash
cd frontend
npm test
npm run build
```
Команда выполняет проверку типов через `tsc` и собирает production-бандл через `vite build` в директорию `dist/`.

### Docker сборка и production запуск
Приложение упаковано в многостадийный `Dockerfile` (`node:22-alpine` -> `nginx:alpine`):
```bash
cd frontend
docker build -t kindergarten-frontend .
docker run -p 3000:80 kindergarten-frontend
```
Nginx слушает порт 80:
- Статические файлы приложения обслуживаются из `/usr/share/nginx/html`.
- Запросы `/api/` проксируются на `http://backend:8080/api/`.
- Запросы `/actuator/` проксируются на `http://backend:8080/actuator/`.
- Роутинг SPA настроен через `try_files $uri $uri/ /index.html;`.
